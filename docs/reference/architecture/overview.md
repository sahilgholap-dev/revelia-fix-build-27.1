# Architecture Overview

Revelia is an AI mystical-reading mobile app: face reading, palm reading, astrology, numerology, compatibility, career destiny, and a combined "Cosmic Blueprint" — all generated by Anthropic Claude models from user photos and birth data. Monetized via RevenueCat subscriptions (Free / Premium / Premium Plus); push re-engagement via OneSignal/FCM. Readings are positioned as entertainment (explicit disclaimer + an "honesty preamble" in every AI prompt).

## Monorepo

No root workspace tooling — `mobile/` and `server/` each have their own `package.json`; install inside each.

## Request flow

Mobile (Expo Router screens → Zustand stores → `lib/api.ts` axios client) → Express backend on Railway (`routes → controllers → services → models`) → MongoDB Atlas. Images go mobile → `POST /upload` → sharp processing → Cloudflare R2; AI calls read the image back from R2. AI generation is centralized in `server/src/services/claude.service.ts`, with Build-27 model routing in `synthesis-routing.ts`.

## The Build-27 "empirical" pipeline (core design shift)

Before Build 27, readings were freeform Claude Vision output — the same photo produced different substance per run. Build 27 inserted a deterministic layer per modality; the LLM now writes **prose only**, never the substance:

| Modality | Deterministic layer | Rules table | LLM's role |
|---|---|---|---|
| Astrology (R1) | Swiss Ephemeris (`sweph`, Moshier mode) natal chart + transits | — | narrates real placements |
| Face (R2) | 68-landmark detection (`@vladmandic/face-api`, tfjs WASM) → `FaceFeatureVector` | `physiognomy-rules.ts` → archetype + traits | prose; `reconcileFaceSubstance` pins the substance |
| Palm (R3) | 21-landmark hand pose (`hand-pose-detection`, tfjs WASM) → `HandFeatureVector` per hand | `chiromancy-rules.ts` → palmType + traits | prose + major-line *flavor* (lines are not measured — geometry-only v1) |
| Numerology (R4) | Pure Pythagorean math, consolidated into `profile.numerology` sub-doc | — | narrates the numbers |

Invariants that keep this stable: extract **once** on stored bytes; taxonomy revisions are a `RULES_VERSION` bump + re-**map** (never re-detect); prose never contradicts the measured substrate; exact CV dependency versions pinned and an `engine{}` stamp stored with each vector.

## Synthesis engine (R5)

All six reading surfaces (daily, weekly, monthly, compatibility, career, name-destiny) route through `createSynthesisMessage` in `server/src/services/synthesis-routing.ts`. Marquee paid surfaces run `claude-fable-5` (streamed, server-side `fallbacks` to `claude-opus-4-8` for policy declines) when `SYNTHESIS_FABLE_ENABLED=true`; the flag defaults **OFF**, which routes them to a guaranteed Opus 4.8 path. Cheap surfaces (daily, free tier, name-destiny) stay on `claude-sonnet-4-6`. Every generation is metadata-logged to the `ai_generations` collection for A/B analysis, from **three** places: `createSynthesisMessage`, `createQaAnswerMessage`, and (since 2026-08-06, P99) `generateFaceReading` / `generatePalmReading` directly — those two are direct Vision calls that reach neither helper and had **never** been logged. See `features/synthesis-engine.md`.
