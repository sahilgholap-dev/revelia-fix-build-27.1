Personalized Cosmic Report · Step 9 mobile mockups

R9 §14 Step 9 (§12u). Screens matched to the live app (dark / indigo / gold), wired to endpoints already live from 3b & 8. Directional fidelity, not final pixels: this is the build reference for Claude Code and the artifact for D6 (Sid / PM) sign-off.

What Step 9 consumes (no backend change)

  • DTO fields: status · highlights.headline · secureLink · expired · tier · resetsAt
  • POST /api/reports (enqueue, self) → 201 or 402
  • GET /api/reports/:id (fresh 1h secureLink per call)
  • GET /api/reports (history, link-less)
  • GET /api/reports/credit (remaining + resetsAt)

The 402 copy split (the thing mobile must get right)

  • Free-locked (tier:'free'): feature is Premium. CTA = upgrade. Sample still viewable.
  • Paid-cap (tier:'premium' + resetsAt): limit is 1/month, not a paywall. CTA = open this month's report, next unlocks on resetsAt.
  • Both return 402 with the same shape; only tier/resetsAt distinguish them. Never show "upgrade" to a paid user.
RESOLVED — the expired state. Owner greenlit a small backend route inside Step 9: an expired report (60-day R2 object gone) can rebuild its PDF from the stored Mongo interpretation, with no re-Fable and no credit charge. Recommended shape: enqueue a re-render the existing worker runs (render → QA → upload), keeping LibreOffice off the API request path. The interpretation is the durable asset; the PDF is a regenerable cache. See screen 9 + §12u DO 7-8.
Assumptions stated inline (flag any to change): entry cards live on both Home/Explore and the Astrology tab; the tapped card opens a single Report hub whose screen is driven by status+tier; generating polls to ready; email is the convenience path, in-app is durable. In-app sample viewer is DEFERRED to a future build — so the sample PDF → R2 upload is no longer a Step 9 gate, and there is no in-app "see before you buy" surface in v1. No face anywhere; palm is self-only.
